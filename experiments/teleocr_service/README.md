# TeleOCR: экспериментальное распознавание выделенного фрагмента

Необязательный отдельный сервис для PicTranslate. Основное расширение, его
настройки по умолчанию и зависимости существующего backend не меняются.

**Это прототип интеграции, а не подтверждение улучшения качества.** Тесты используют
подставной OCR; реальная модель, GPU, скорость и качество на манге требуют
отдельной проверки. Сервис не устанавливается и не запускается автоматически.

## Область первой версии

- `POST /ocr`: распознать один фрагмент без переводчика — для сравнения с Tesseract.
- `POST /translate`: OCR, затем отдельный OpenAI-совместимый **текстовый** переводчик.
- `GET /health`: доступность процесса и признаки конфигурации. `ok: true` не означает,
  что модель загружена или inference проверен.
- Ответ совместим с существующим серверным `CustomAdapter`.
- `boxes: []`: автоматического поиска пузырей и выдуманных координат нет.
- Модель загружается лениво, один раз, из **локального каталога**. Загрузка Hub
  в runtime отключена. OCR-запросы сериализованы; ожидание занятой модели ограничено.
- Нет автоматического fallback, нового переключателя OCR в UI, изменения движка
  `local`, пакетного разбора документов или обязательной зависимости от GPU.

## Изоляция окружения

TeleOCR upstream требует Python `>=3.10,<3.13`. Рекомендуется отдельный Python 3.12
venv. Существующий Docker backend PicTranslate на Python 3.13 менять не нужно.
Не устанавливайте TeleOCR в его окружение.

Сначала проверьте доступность GPU/драйвера и совместимость выбранного backend.
Основной upstream-путь — CUDA/vLLM; вариант `transformers` в коде допускает CPU,
но скорость на CPU здесь не измерена. Объём нужной VRAM не гарантируется.

Из корня PicTranslate, Linux/macOS:

```bash
python3.12 -m venv .venv-teleocr
.venv-teleocr/bin/python -m pip install -r experiments/teleocr_service/requirements.txt
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv-teleocr
.\.venv-teleocr\Scripts\python.exe -m pip install -r experiments/teleocr_service/requirements.txt
```

`.venv-teleocr/` исключён из git. Веса модели храните вне репозитория.

## Upstream и модель: явное подключение

Проверенный интерфейс относится к TeleOCR commit
`1e71f4fe792d12bbb86d2671c5ed6f3a1499b27d`:
https://github.com/caipeng328/TeleOCR/tree/1e71f4fe792d12bbb86d2671c5ed6f3a1499b27d

После проверки upstream-кода и условий использования установите этот commit
в **отдельное окружение**:

```bash
python -m pip install "TeleOCR @ git+https://github.com/caipeng328/TeleOCR.git@1e71f4fe792d12bbb86d2671c5ed6f3a1499b27d"
```

Здесь `python` должен быть интерпретатором отдельного venv, не системным и не backend.
Установка upstream добавляет тяжёлые ML-зависимости, включая vLLM даже для
Transformers-пути. Она не выполнялась при проверке этого прототипа.

Заранее скачайте и проверьте **полный локальный snapshot** модели
https://huggingface.co/StarDoc-AI/TeleOCR и укажите его каталог.
Зафиксируйте revision модели в журнале эксперимента; не используйте изменяемый
`main` для воспроизводимого сравнения. Snapshot должен включать веса, processor,
конфигурацию и требуемые файлы custom code.

Upstream использует `trust_remote_code=True`: после загрузки это исполняемый код,
не только данные. Просмотрите его до запуска. Лицензия весов в карточке —
Apache-2.0; в проверенном GitHub-снимке отдельного LICENSE нет. Не копируйте
upstream-исходники в MIT-проект без уточнения лицензии. Этот сервис содержит только
собственную обёртку и импортирует отдельно установленный пакет.

## Конфигурация и запуск

Скопируйте `experiments/teleocr_service/.env.example` в `.env` рядом с ним.
Укажите локальный каталог модели. Не коммитьте `.env`, ключи, веса и изображения.

- `TELEOCR_BACKEND=transformers` — первый эксперимент; `vllm-engine` — явная альтернатива.
- `TELEOCR_SERVICE_TOKEN` — необязательный Bearer-токен для клиента backend.
- `MT_BASE_URL`, `MT_MODEL` — отдельный текстовый переводчик для `/translate`.
- `MT_API_KEY` — только если выбранный переводчик требует авторизации.
- Для `/ocr` настройки MT не нужны. `/translate` без них возвращает 503,
  а не выдаёт исходный текст за перевод.

Из корня репозитория, с активным отдельным venv:

```bash
python -m uvicorn experiments.teleocr_service.app:app \
  --host 127.0.0.1 --port 8011 --workers 1 \
  --env-file experiments/teleocr_service/.env
```

В PowerShell используйте одну строку команды вместо `\` для переноса.
**Один worker**: несколько процессов загрузят несколько копий модели.
Не включайте `--reload` для измерений. Не публикуйте порт в интернете.

Если MT локальный, изображение и текст могут остаться на машине. При облачном MT
распознанный текст уходит выбранному провайдеру. Это отдельное явное решение;
облачный перевод не включается автоматически. Изображение MT-провайдеру не отправляется.

Лимиты первой версии: 5 MiB сжатого изображения, 4 млн пикселей, PNG/JPEG/WEBP без
анимации. Превышение — 413, неизвестный формат — 415. Занятый OCR — 503 с Retry-After.
Чтение файла ограничено, но ASGI multipart-парсер принимает тело до вызова endpoint:
для публичного размещения дополнительно нужен входной лимит тела/прокси и защита
от перегрузки. Этот прототип предназначен для доверенного локального использования.

OCR-поток нельзя безопасно остановить отменой HTTP-запроса: работа модели завершится
в фоне с удержанием lock. Для зависшего inference потребуется перезапуск сервиса.
Таймаут MT — 45 секунд; ошибки провайдера не возвращают его тело или ключи клиенту.

## Подключение через существующий backend

Для backend, запущенного **нативно на той же машине**, задайте в `backend/.env`:

```dotenv
CUSTOM_API_URL=http://127.0.0.1:8011/translate
CUSTOM_MODEL_NAME=teleocr-crop
# CUSTOM_API_KEY должен совпадать с TELEOCR_SERVICE_TOKEN, если токен включён.
OCR_TIMEOUT_SECONDS=120
TRANSLATE_TIMEOUT_SECONDS=120
# Для сравнения разных OCR/MT отключите существующий backend-кэш:
REDIS_URL=
USE_FILE_CACHE_IF_NO_REDIS=false
```

Это пример стартового бюджета, а не измеренная скорость. Первый прогрев модели
может длиться дольше. Существующий браузерный HTTP-клиент имеет таймаут 90 секунд,
поэтому увеличение backend-таймаута не увеличивает ожидание в браузере.

Если backend в Docker, `127.0.0.1` — сам контейнер, а не машина хоста.
Нужен отдельно проверенный сетевой маршрут; данный пример для Docker не подходит.

В расширении: движок **backend**, модель **custom**. Выделите один пузырь/фрагмент.
Ответ использует существующую плашку выделения. Откат: верните предыдущий движок
или модель и остановите TeleOCR-сервис.

**Ограничение:** выбор `backend/custom` глобален — он затрагивает и полные изображения,
если пользователь запускает их перевод. В первой версии нет кнопки «только этот
фрагмент через TeleOCR». Для чистого эксперимента используйте `/ocr` или перевод
только выделения; полноценный выбор OCR на одну задачу — отдельная итерация.
Не подключайте этот endpoint к браузерному **Custom AI**: это другой протокол.

## Тесты интеграции без GPU

В отдельном тестовом окружении:

```bash
python -m pip install -r experiments/teleocr_service/requirements-dev.txt
PYTHONPATH=backend:. python -m pytest -c experiments/teleocr_service/pytest.ini experiments/teleocr_service/tests -q
```

PowerShell перед тестами: `$env:PYTHONPATH = "backend;."`, затем та же команда pytest
без POSIX-префикса `PYTHONPATH=...`.

Проверяются OCR/MT-контракт, настоящий CustomAdapter с ASGI-сервисом, отсутствие MT
при пустом OCR, лимиты, ошибки, Bearer-аутентификация и сериализация запросов.
ML-пакет и веса не импортируются тестовым inference.

## Проверка качества: следующая стадия

Возьмите 30–50 реальных фрагментов с ручной транскрипцией. Для каждого сохраните
локально: идентификатор, исходный язык, ожидаемый текст, OCR-вывод, итоговый перевод,
время холодного/тёплого запроса, модель/revision, аппаратную конфигурацию.
Не коммитьте приватные изображения или полный текст без согласования.

1. Tesseract и TeleOCR с **одинаковым MT**: ошибки символов/слов, пропуски и порядок.
2. Лучшая связка против текущего AI Vision: качество перевода и задержка.
3. Отдельные группы: английские пузыри, вертикальный японский, SFX, плохой контраст.
4. Критерий принятия заранее: заметное уменьшение OCR-ошибок на проблемных фрагментах
   без неприемлемой задержки; не средний документный benchmark из README модели.

До этой проверки сервис остаётся экспериментальным и выключенным по умолчанию.
